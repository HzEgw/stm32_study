# 03 · `socat` 虚拟串口：**pts 编号每次都会变** —— 以及"乱码 U"是怎么来的

> **记录时间**：2026-09-24
> **触发场景**：R 线 W1 收口 —— 用 `socat` 造一对虚拟串口，给 `uart_bridge` 灌假帧，验证 `/mcu/frame`（`04` §3.1）
> **分类判定**：拿掉 ROS2 成立、换到任何 Linux 场景也成立（`/dev/pts/*` 是 Linux 终端设备）→ **工具/环境问题** ✅
> **归属**：本文件夹（收录范围里的"**终端环境**"）

---

## 1. 一句话结论

1. `socat ... pty,raw,echo=0 pty,raw,echo=0` **每次启动分配到的 `/dev/pts/N` 编号都不一样** →
   **文档里的 `5/6` 只是示例；唯一权威 = socat 自己打印的那两行 `PTY is /dev/pts/xx`**。
2. **桥的 `port` 指向哪一端，就必须往"另一端"写**：写进桥自己那一端 → 数据被 socat 转到另一端 → **没人读 → 静默丢弃**。
3. **往"终端窗口"的 pts 写字节 → 那些字节会变成"键盘输入"被显示出来** →
   这就是当天看到的"**乱码 U**"（`0x55` 正好是 ASCII 的 `U`）。
4. **`open()` 成功 ≠ 它是串口**：任何**存在且可写**的 pts 都能"打开成功"，必须**写一帧看反应**才能验证。

---

## 2. 现象（原样保留）

```
# socat 打印（唯一权威编号）
2026/09/24 13:59:04 socat[14263] N PTY is /dev/pts/21
2026/09/24 13:59:04 socat[14263] N PTY is /dev/pts/22

# 桥（错用了 23 —— 那是别的终端的 pts）
[INFO] [1790229555.939799462] [uart_bridge]: 串口已打开: /dev/pts/23 @ 115200 8N1

# 三个对照实验
printf '\xAA\x55\x02\x00\x07\x09' > /dev/pts/21   →  无反应
printf '\xAA\x55\x02\x00\x07\x09' > /dev/pts/22   →  无反应      ← 因为桥当时在 23
printf '\xAA\x55\x02\x00\x07\x09' > /dev/pts/23   →  乱码 U      ← 23 是终端，不是 socat
```
**把桥改到 21 之后**：`printf '\xAA\x55\x02\x00\x07\x09' > /dev/pts/22` → `/mcu/frame` 立刻出 `data: [0, 7]` ✅

---

## 3. 为什么会这样（原理）

### 3.1 拓扑：socat 用两个"主端"把两个"从端"对连

```
   你写这一端                                     桥读这一端
 /dev/pts/22  ⇄  /dev/ptmx(主2) ─── socat ─── /dev/ptmx(主1) ⇄  /dev/pts/21
      ↑ 写                                                      ↑ 读（桥）
```
- 写 `slave` → 数据出现在**它自己的 master** 上 → socat 读出来 → 写到**另一个 master** → 出现在**另一个 slave** 上；
- 那一端**若没人读 → 数据被丢掉**（这就是"写了没反应"的原因）。

### 3.2 为什么编号每次都会变

`/dev/pts/N` 由内核 `devpts` **动态分配**（释放后会被复用），实际拿到几号取决于**当时开着的终端数量**。
→ 所以**不能记编号**，只能每次**从 socat 的输出里抄**。

### 3.3 为什么"乱码 U"（这条最有用）

终端会把从 pty 收到的字节按"**键盘输入**"渲染：

| 字节 | 终端表现 |
|---|---|
| `0xAA` | 乱码（不是合法的 UTF-8 起始字节） |
| **`0x55`** | **`U`** ← ASCII 0x55 就是 'U' |
| `0x02` `0x00` `0x07` | 不可见的控制字符 |
| `0x09` | TAB |

→ **看到"乱码 + U"就说明：你的帧被灌进了一个终端，而不是 socat 的虚拟串口。**

### 3.4 为什么"串口已打开"靠不住

`open()` 只检查两件事：**路径存在 + 我有权限**。任何 pts 都满足 → 桥照样打印"打开成功"。
→ **判据只能是"写一帧，看对面有没有数据"。**

## 4. 正确做法（三层保险）

```bash
# ① 最稳：给 socat 固定软链（编号再怎么变都与你无关）
socat -d -d pty,raw,echo=0,link=/tmp/ttyA pty,raw,echo=0,link=/tmp/ttyB
ls -l /tmp/ttyA /tmp/ttyB          # 必须显示 -> /dev/pts/NN
#   桥：ros2 run uart_bridge uart_bridge_node --ros-args -p port:=/tmp/ttyB
#   你：printf '\xAA\x55\x02\x00\x07\x09' > /tmp/ttyA

# ② 备选：现场验号（3 秒，不用记编号）
ls -l /proc/$(pgrep -x socat | head -1)/fd/ | grep -E 'ptmx|pts'       # socat 手里是哪两个
ls -l /proc/$(pgrep -f 'lib/uart_bridge/uart_bridge_node')/fd/ | grep pts   # 桥开的是哪个
#   规则：桥的 pts 必须是 socat 那两个之一 → 你写【另一个】

# ③ 兜底：桥的 port 只能【启动时】改（节点没有参数回调）
#   → 改端口必须 Ctrl+C 重启节点，ros2 param set 不会重新打开串口
```

## 5. 正确 ✗ 错误 对照

| ✗ 错误做法 | ✅ 正确做法 |
|---|---|
| 用文档里的示例编号 `5/6` 直接敲 | **抄 socat 打印的那两行**（或用 `link=` 固定名） |
| 桥和"写出"指向**同一个** pts | 桥一头、你写另一头（两端互连） |
| 看到"串口已打开"就认为通了 | 必须**写一帧看到数据**才算通 |
| 写之前不验号 | 先 `ls -l /proc/<pid>/fd` 验号（§4 ②） |
| socat 重启后沿用旧编号 | 重启后**重看编号**，或直接上 `link=` |

## 6. 口诀 & 排查清单

> **口诀：编号每次变，只抄它打印的两行；桥开一头、你写另一头；"串口已打开"不等于通了 —— 写一帧才算数。**

| # | 症状 | 先查什么 |
|:---:|---|---|
| 1 | 写了没反应 | 桥的 pts 是不是 socat 那两个之一（§4 ②） |
| 2 | 某个终端出现乱码（尤其带 `U`） | 你写的是**终端**的 pts，不是 socat 的 |
| 3 | 重启 socat 后失效 | 编号变了 → 重看两行 / 改用 `link=` |
| 4 | 改了 `port` 参数没反应 | 桥只在**启动时**读参数 → **重启节点** |
