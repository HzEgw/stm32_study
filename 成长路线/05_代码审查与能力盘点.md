| 呼吸灯 / 跟随式调光（你现在的 1 kHz） | **关预装载**（= 现状） | 写 `CCR` 立即生效、**跟手**；代价是"本周期中途改值 → 该周期出现 1 个畸形脉冲"，1 kHz 下肉眼不可见 |
| 电机 / 舵机 / 精密调光 | **开预装载**：`TIM_OC2PreloadConfig(TIM2, TIM_OCPreload_Enable)` | 新值在**下个更新事件**统一搬入 → **每个周期占空比完全一致**、绝不产生半周期怪脉冲；延迟 ≤ 1 个 PWM 周期（**20 kHz 时仅 50 µs**，对转速无感） |

> 一句话：**不是"一律关掉"，而是"跟手 ↔ 无毛刺"二选一**。
> 控制它的位是 **`CCMR1.OC2PE`(bit3) / `CCMR2.OC3PE`(bit3) / `CCMR2.OC4PE`(bit3)**，API 是 **`TIM_OC2/3/4PreloadConfig()`** —— 这条记住，你"看到 API 想不到寄存器"就少一格。

### 8.7.3 回答核心疑问："我是否真的有必要再写一次寄存器的操作？"

**不必重写工程**；要练的是**"双向翻译"**（每天 10 min 足够）：

| 方向 | 练法 |
|---|---|
| **API → 位** | 每用一个库函数，注释补一行"它改了谁"：`TIM_Cmd(TIM2,ENABLE)`→`CR1.CEN(bit0)`；`TIM_SetCompare2`→`CCR2`；`TIM_OC2Init`→`CCMR1.OC2M[6:4]+CC2S+CCER.CC2E/CC2P`；`TIM_TimeBaseInit`→`PSC/ARR/CR1(CMS·DIR)/CKD` **+ `EGR.UG` 产生 1 次更新事件**；`TIM_ClearFlag`→`SR.UIF` 清零 |
| **位 → 现象** | 反过来推：频率不对 / 占空比不变 / 输出反相 → 哪个位？**这才是排错能力**（你 09-21 能推出 `EGR.UG`，就是这条肌肉） |
| **看库实现** | Keil 里对函数按 `F12` 跳进 `stm32f10x_tim.c` 看那 10 行，**只看不改**；每周 5 个 API → 两周覆盖 TIM/GPIO 常用面 |
| **Watch 观察** | 调试时把 `TIM2->CCMR1 / CCER / CR1 / CCR2` 加进 Watch，**单步**跑库函数看位变化 → 建立映射最直观的方法 |
| 何时真手写寄存器 | ① 库没封装的位 ② 时序敏感/要原子操作 ③ 排错要绕过库 —— **不是"为了学而重写"** |

> 结论：**"知道流程"已经很值钱**；下一步是把"流程"升级为**"位级因果"**。上表就是"看到 API 能否想到寄存器"的唯一解。

**⚠️ 设计级冲突（"统一到 TIM2"这条路线的根本症结）**
同一个 TIM2 的 **`PSC/ARR/CNT` 是共享的**：
1. PWM 要 `PSC=719 / ARR=99` 才有 1 kHz；而测周法要求 **`ARR+1 ≥ fc × T被测`**（fc=1 MHz、测 1 kHz → 需 **≥1000** 个计数）
2. 两者**只有一个 ARR**：取 `99` → 测 1 kHz 时 `CNT` 先溢出、捕获值崩掉；取 `≥1000` → PWM 频率变成 `1 MHz/(ARR+1) ≤ 999 Hz`
3. 更要命的是**逻辑闭环**：当"被测信号"就是本定时器的 PWM 输出时，**必然 `N ≡ ARR+1`**（PWM 周期本身就是 `ARR+1` 个 fc 计数）→ `IC_GetFreq()` 永远等于 **PWM 频率自己** ⇒ 这不是测量，而是**用公式验证公式**（等于没测）

→ **结论：必须分两个定时器**（江协第 7 章即此结构）：
- **PWM** = `TIM2_CH1 / PA0`：`PSC=719`、`ARR=99`、`CCR=50`
- **捕获** = `TIM3_CH1 / PA6`：`PSC=71`（fc=1 MHz）、`ARR=65535`、**从模式复位（TI1FP1 + Reset）**
- 跳线 **PA0 ↔ PA6**（自己测自己，闭环验证）

> 可选替代（若坚持"只用一个定时器"）：把捕获放 **CH2/PA1**（`TIM_Channel_2` + `TIM_TS_TI2FP2` + 读 `TIM_GetCapture2`）+ 跳线 PA0↔PA1 —— 能跑，但**精度与量程被共享的 ARR 卡死**（`ARR+1` 既定 PWM 周期又定捕获窗口），只适合当"演示"，不适合当验收。

### 8.10.4 ⭐ 两处"要你自己解释"的技术点（进笔记，不是给我看）

1. **`+1` 与否：差一次 Watch 就能定案** —— Reset 从模式下两次上升沿之间 CNT 走 `0…N-1`、并在第 N 个沿把计数值锁进 `CCR1`，所以 `f = fc/N` 与 `fc/(N+1)` **只差 1 个计数（1 kHz 下 ≤0.1%）** ⇒ **你的 `[900,1100]` 判据两种都能过，分辨不出对错**。定案只需要一个数：**Watch 里记一次 `TIM3->CCR1` 和 `IC_GetFreq()`**（若 `CCR1≈1000` → 你的公式更准；若 `≈999` → `+1` 版更准）。**这就是 §9.3 ①「把验证变成条件反射」的最小动作。**
2. **`ARR=65535` 的量程与分辨率**：`fc=1 MHz` → 最长可测周期 **65.535 ms（≈15.3 Hz）**；测 1 kHz 时 `CCR1≈1000` ⇒ **量程只用了约 1.5%，余量巨大，代价是分辨率只有 1/1000**。以后要测更高频（如 >5 kHz）应调小 `PSC` 或改用频率法 → **写进 README 的"已知限制"**。

#### C. 为什么"不清零就会连带拖 W3 的 S2"

S2（编码器 + **开环调速**）要用 PWM 驱动电机**正反转**，而官方就是"**双 PWM、5 kHz**"（`02` §2.3 / 映射表：STM32 侧建议 **TIM1_CH1/CH2 或 4 路双 PWM**）。
→ 若 S1 只停在"1 kHz / 3 路 / 单端"，到 S2 就得**同时**改"频率 + 通道 + 引脚 + 驱动方式"—— 一个台阶里叠 4 个变量，正好违反"**每次只引入一条新知识**"（`03` §4），一卡就是好几天。
→ 所以 **S1 的 ①②（四路 + 5 kHz）在 10-03 前清零 = 给 S2 铺平路**（v1.30：③④ 已改性质，**不阻塞 S2**；原写"四项 10 月底前清零"作废）。
