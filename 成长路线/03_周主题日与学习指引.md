# 03 · 周主题日与学习指引（工作日 2h × 5 + 周末 5h × 2 = **20 h/周**）

> **为什么要单独一个文件**：`00_8个月学习计划` 管"8 个月到哪一步"，本文件管"**每天怎么过**"。
> 打印出来贴在桌上，**照做即可 —— 不用每天做决策**（决策本身最耗意志力）。
>
> **时间预算**：周一~周五 **每天 2h** + 周六 **5h** + 周日 **5h** = **20 h/周 ≈ 80 h/月**（8 个月 ≈ 650 h）。
> ⚠️ 与旧版"25h/周"的差异：**按 20h 排**，多出来的时间当奖励，不当欠债。
> **周的起止**：**每周从周日算起、到周六结束** → W1 = **09-20(日) ~ 09-26(六)**，之后每周 +7 天。
> 每周日先做 **30min 复盘**（收尾上一周），再进入当周任务；**09-19（周六）晚不计入 KPI**（只读文件 + 建目录）。

---

## 0. 主题日制度（为什么这样排）

| 设计 | 解决的问题 |
|---|---|
| **每天固定"主题日"** | 免决策：到点就知道今天碰什么，不用"今天学啥好" |
| **两条线各有固定入口** | 不丢线：ROS2 有专用日，不会被 STM32 挤掉（这正是你要的"恢复期"保障） |
| **周末只做"整段任务"** | 搭环境/联调/调 PID 这类事一旦被打断就白干，必须放大块 |
| **每个学习块都有落盘** | 比赛材料自动积累，不用最后"回忆式补材料" |

**三条铁律**：
1. **收尾 5 分钟必须落盘**（存文件 / `git commit` / 写 3 行日志）；
2. **周日必复盘**（三问 + 更新 `00` 打卡表）；
3. **不熬夜**（20h 是可持续节奏，通宵会毁掉下周）。

## 1. 一周全景（主题日表 —— 打印这一张就够）

| 天 | 时长 | 主题日 | 主任务 | 落盘到哪 |
|---|---|---|---|---|

| **周二** | 2h | 🐢 **ROS2 回炉日** | R 线：命令 → 节点 → 包（恢复期按第 4 节走） | `~/ros2_ws` + `notes/commands.md` |

## 2. 20 h 怎么分（两条主线 + 一条恢复线）

| 线 | 每周 | 拆解 | 说明 |
|---|---|---|---|
| **A｜STM32 主线** | **9 h** | 周一 2 + 周三 2 + 周六 5 | 写代码、调硬件、做实验（比赛硬通货） |
| **R｜ROS2 恢复线** | **6 h** | 周二 2 + 周四 2 + 周日 2 | **恢复期 W1~W4 固定 6h**；W5 起降到 4h 并转为"实车对接" |
| **B｜成果/归档** | **2 h** | 周五 2 | 笔记、git、问题清单、选题材料（把 A 变成成绩） |
| **联调/实验/弹性** | **2.5 h + 0.5 h 复盘** | 周日 3h | 跨线任务（MCU ↔ ROS2 联调）与补课；最后 30min 复盘归档 |
| 合计 | **20 h** | — | 技术为主、成果不断线 |

> 比例可调，但**两条线的"入口日"不要动**：动了就会连续几周不碰 ROS2（你上次就是这么断掉的）。

## 3. 每日 2 h 的"4 段式"时间盒（照抄即可）

| 时间 | 做什么 | 规则 |
|---|---|---|
| 00:00–00:10 | **开场**：读昨天落盘的"下一步"（3 行），写下**今天唯一目标** | 目标要能一句话验证（"让 `g_whoami` 读到 0x68"） |
| 00:10–01:00 | **第一段：动手**（写代码 / 接线 / 跑命令） | **不查资料**，遇到不会的先记住 |
| 01:00–01:05 | 休息 | 真的离开椅子 |
| 01:05–01:45 | **第二段：攻坚**卡点 | 自己查**限时 10 分钟**；超时 → 记进"问题清单"，继续推进能做的部分 |
| 01:45–02:00 | **收尾**：落盘 + 写 3 行日志 | 做了什么 / 卡在哪 / 明天第一步 |

**周六 5h** = 2h 段 + 休息 30min + 2h 段 + 30min 收尾（含截图/录像）。
**周日 5h** = 2h ROS2 + 2.5h 联调/实验 + **30min 复盘归档**（复盘是独立环节，不算学习时间）。

## 4. ROS2 恢复期 4 周路线（**本文件最重要的一节**）

> 前提：你已经 **1.5 个月没碰 ROS2**。恢复期**不能从新知识开始**，要先把"你已经会的东西"重新跑起来，
> 让手和脑重新接上。你已有的资产很厚：Ubuntu 22.04 + Humble、C++、自定义 msg/节点/launch/参数、
> `ros2_control + Gazebo` 差速仿真**跑通过**，还有现成的 `ros2_ws_src\uart_bridge`（我写的桥）可当恢复素材。

**恢复三原则**
1. **不重装系统、不追新发行版**（就用 Ubuntu 22.04 + Humble，别折腾 24.04/Jazzy）；
2. **每次只引入一条新知识**，其余全是"复习 + 敲命令"；
3. **每个会话留下能复现的命令**（写进 `~/ros2_ws/notes/commands.md`）——这就是你的"外置记忆"。

| 周 | 恢复目标 | 周二 2h | 周四 2h | 周日 2h | 通过标准 |
|---|---|---|---|---|---|
| **W1**<br>09-20~09-26 | 环境体检 + 命令肌肉记忆 | `ros2 doctor`；`ros2 topic list/hz/echo`、`ros2 node list`、`ros2 service list`、`ros2 param list` **逐个过一遍**（找现成的仿真/示例节点练手） | 把 Windows 侧 `ros2_ws_src\uart_bridge` **用 git 拉到 Linux `~/ros2_ws/src`**，`colcon build --symlink-install` 编译成功 | `source install/setup.bash` 后 `ros2 run uart_bridge uart_bridge_node` 启动（没串口也应"启动成功 + 打开失败"的错误清晰）；`ros2 topic list` 能看到 `/mcu/frame` | 不看笔记能说出 **8 个常用命令**的作用；包能编译能跑 |
| **W2**<br>09-27~10-03 | 参数 + launch + bag | 给 `uart_bridge` 加 3 个参数（串口名/波特率/发布周期），用 `ros2 param set/get/list` 运行时改 | 写/改 `.launch.py` 一次启动；`ros2 bag record -o demo /mcu/frame` 录 30s，`ros2 bag info` 查看 | `ros2 topic echo --once` 对比 bag 回放；把命令清单补进 `notes/commands.md` | 一条 `ros2 launch` 启动全部；bag 能录能回放 |
| **W3**<br>10-04~10-10 | 自定义接口 + TF | 自定义 `msg` 或 `srv`（仿官方 `fishbot_interfaces/FishBotConfig`：key/value），改 CMake 并编译 | 用自定义 msg 发一帧 MCU 数据；`ros2 interface show` 验证字段 | TF 复习：`static_transform_publisher` 搭 `odom → base_footprint → laser` 链，`rviz2` 看 frame 是否正确 | 自定义 msg/srv 能收发；TF 树在 rviz2 里正确 |
| **W4**<br>10-11~10-17 | **Gazebo 回炉（重建信心）** | 复现你**上次已经跑通**的 `ros2_control + Gazebo` 差速仿真（不要加新东西） | 在仿真里发 `cmd_vel`，观察轮子转动与里程计输出 | 与实车对照：记录官方固件侧 `/odom` 数据（此时已能读参数），做一页"仿真 vs 实车"对照表 | **30 分钟内**能重现仿真；对照表落盘 |
| **W5 起** | 转入实车对接（正式线） | ROS2 时间降到 **4h/周**；内容转为 `micro-ros-agent` + 官方固件 + 自研 STM32（见 `00` §13 micro-ROS 专项路线） | — | — | 以 `00` 的 W 计划为准 |

> 💡 **恢复期最好的教练是"已知的失败"**：把 `uart_bridge` 编译时的每个报错都记下来（缺依赖？路径？），
> 这些就是你 W8 做 micro-ROS 时会再次遇到的坑，提前趟平。

## 5. 主题日卡片（复制到便签 / 打印贴桌）

**🔧 周一、周三 · 电控日（STM32）**
- 只碰：`01~06` 工程 / Keil / 示波器 / 万用表（**不开 Linux**，避免分心）
- 开场 3 行：昨天落盘的"下一步"
- 收尾必做：Save All → 关键变量截图 → 3 行日志 → 更新工程 README

**🐢 周二、周四 · ROS2 日**
- 先 `source /opt/ros/humble/setup.bash`（写进 `~/.bashrc`，别每次手打）
- **每条命令跑完就复制进** `notes/commands.md`
- 卡住超 20 分钟 → 记进问题清单，切到"能做的部分"（不要在一个报错上空转 2 小时）

**📦 周五 · 归档日**
1. `git add -A && git commit -m "..." && git push`
2. 笔记/截图/数据归位（`docs/media`、`docs/data`、`docs/logs`）
3. 写"下周三步走"（**不超过 3 条**，其中必须含 1 条 ROS2）

**⚒️ 周六 · 攻坚日（5h）**
- 只安排"需要连续 2 小时以上"的任务：搭环境、联调、调 PID、跑对比实验
- 被打断一次 = 这次攻坚"打折"，记录原因（保护大块时间是你最大的竞争优势）

**🎯 周日 · 产出日（5h）**
- 2h ROS2（按第 4 节当周任务）→ 2.5h 联调/实验 → **30min：复盘三问 + 更新 `00` 打卡表 + 素材归位**

## 7. 降级方案（考试周 / 加班 / 生病：**断进度可以，断线不行**）

| 情况 | 保底动作 |
|---|---|
| 今天只有 30 分钟 | 只做一件小事：跑一条 ROS2 命令 + 写进 commands.md，或给 STM32 代码补注释/看一个 Watch |
| 整周课业爆炸 | **保 GPA 优先**：本周只保留"周五归档 + 周日复盘"，技术线暂停；但**绝不连续两周无产出** |
| 一个 bug 卡 3 天以上 | 换主题日（去做另一条线），把问题写进清单，周五集中查/提问（换个脑子常常就通了） |
| 状态差、完全不想学 | 只做"读 10 分钟自己以前的笔记"——**保持接触**比学多少重要 |

## 8. 与主计划的接口（两句话）

1. 本文件管"**每天怎么过**"；`00_8个月学习计划` 管"**8 个月到哪一步**"；`README.md` 管"**换会话怎么接上**"。
2. **每周日 30 分钟复盘**时做三件事：更新 `00` 的打卡表一行 → 素材归位 → 写下"下周唯一目标"（贴在本文件顶部）。
3. 阶段变化时**只改本文件的第 1、4 节**（例如：W7 起电控日换成 HAL/micro-ROS，12 月起周六改为整机联调）。
