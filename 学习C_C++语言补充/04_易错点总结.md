# 04 · 易错点总结（这次的误区 + 工程常见坑）

## A. 我这次弄错 / 弄混过的概念

| # | 我原来的想法 | 正确的说法 | 为什么错 |
|---|---|---|---|
| 1 | "static 变量只允许在 static 函数里修改" | **C 里任何本文件内的函数都能改 static 变量**；C++ 里任何成员函数（含普通成员函数）也都能改静态成员 | 把 **C++/Java 的"类作用域 + 权限"**概念套到 C 上了 |
| 2 | "static 是一种访问控制/安全机制" | static 只管**名字的可见范围（链接性）**；拿到指针照样能改 | C 里没有 private |
| 3 | "在 main.c 里应该能看到别的 .c 的 static 函数" | 看不到也用不了：**链接器层面根本没有这个符号** | `#include` 只是文本粘贴，不是"导出/导入" |
| 4 | 以为 `#include "x.h"` 就能用 x.c 里的东西 | 头文件里只有**声明**时才有用；真正靠**链接器按符号名匹配** | 混淆了"文本包含"和"符号链接" |
| 5 | "只有静态函数能访问静态成员" | 方向记反了：是**静态函数不能访问非静态成员**（没有 this） | 口诀：**静态函数受限制，静态成员不受限制** |
| 6 | 忘了 `static` 在**函数内部**是另一层含义 | 函数内 `static` 局部变量是"生命周期变长"，**不改可见性** | 一个关键字，两种含义 |

## B. 工程里最容易踩的坑（含 C/C++ 语言层 + 环境层）

| # | 坑 | 现象 | 正确做法 |
|---|---|---|---|
| 7 | 中断与主循环共享的变量**不加 volatile** | 偶发读到旧值；"加一行打印就好了"这种诡异 bug | 加 `volatile`；多字节再加临界区 |
| 8 | 用 `volatile` 当原子/同步 | 多字节数据撕裂、竞态仍在 | 关中断 / 双缓冲 / C11 原子 |
| 9 | 头文件里写 `static` 变量或函数 | 每个 include 它的 .c 各生成一份副本（费 Flash、可能重名） | 头文件只放声明、宏、类型；私有实现放 .c |
| 10 | 给中断服务函数 / `main` 加 `static` | 链接报 `Undefined symbol TIM3_IRQHandler (referred from startup_*.o)` | 被启动文件按名字引用的函数**必须**外部链接 |
| 11 | C++ 里中断函数忘了 `extern "C"` | 名字被修饰（name mangling）→ undefined symbol | `extern "C" void TIM3_IRQHandler(void)` |
| 12 | C++ 类静态成员只声明未定义（C++17 前） | `undefined reference to 'X::s_member'` | 类外写一次定义：`uint32_t X::s_member = 0;` |
| 13 | 为了消除 IDE 报错，在 `HARDWARE/` 放一个假的 `stm32f10x.h` | Keil 的 Include Paths 里 `.\HARDWARE` 排在库路径之前 → **优先包含假头文件**，满屏未定义 | 让 IDE 配置指向真库（改 `includePath`），**永远不要伪造库头文件** |
| 14 | Keil 里漏写 `STM32F10X_MD` | `#error "Please select first the target STM32F10x device..."` | 和代码里的配置保持一致（寄存器版只写这一个；标准库版再加 `USE_STDPERIPH_DRIVER`） |
| 15 | 用万用表"看 PWM 波形" | 读数不是峰值而是**平均值 ≈ 3.3V × 占空比** | 正确的用法：这样看占空比；要看波形用示波器 |
| 16 | 编码器 `ENC_PPR` 与实际线数不符 | 转速/位置成比例地错 | 按编码器铭牌改 `ENC_PPR`、减速比 `ENC_GEAR` |
| 17 | 占用 PA13/PA14（SWD）做普通 IO | ST-Link 连不上，第一次下载就被"锁死" | 保留 SWD；要用 PB3/PB4/PA15 时注意 JTAG 复用 |
| 18 | 在中断里做除法/打印等重活 | 系统实时性变差、丢中断 | 中断只取数、置标志；计算放主循环（我们 02/03 都是这么写的） |

## C. 每次写新模块时的自查清单（5 条）

1. 这个变量会被**中断/其他上下文**改吗？→ 加 `volatile`
2. 它需要被**别的 .c** 用名字访问吗？→ 不需要就 `static`；需要就在头文件里声明
3. 它是**多字节**且并发访问吗？→ 关中断 / 双缓冲
4. 这个函数会被**启动文件/其他模块按名字调用**吗？→ 会：不能 static（C++ 还要 `extern "C"`）
5. 我是在解决"看不见"的问题吗？→ 那是**头文件 + 链接**的事，不是加/去 static 能解决的

---

## D. 一句话总纲（背下来）

> **`static` 管"名字在哪个文件里存在"；`volatile` 管"每次都要真的去内存读写"；
> `const` 管"只读"；`extern` 管"定义在别的文件里"。
> 它们都不是访问控制 —— C 里没有 private，"只能通过接口改"要靠 `static` 数据 + 头文件只暴露函数。**
