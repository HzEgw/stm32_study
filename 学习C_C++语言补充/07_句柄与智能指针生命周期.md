# 07 · "句柄"到底是什么？—— `create_publisher` 返回的 `SharedPtr` 不保存会怎样

> **记录时间**：2026-09-20
> **触发场景**：写 W1 发布者时想不通——为什么 `create_publisher` 要用 `pub_ = ...` 存成成员？
> 为什么不直接把指针弄成堆上的、让发布者"一直都在"？
> **原始疑问（自己 README 原文摘录）**：
> > "我对句柄的概念就是 create 函数回传回来的智能指针…… 智能指针是有生命周期的，
> > 构造结束了之后就需要把临时智能指针传回去，不然没有引用计数，我的 publish 类也会被析构。
> > 但是我之前一直在思考的一个问题就是，为什么不直接在构造 publish 等这一类"功能"时候，
> > 直接把临时指针变成堆区的指针？"
> **对应源码**：`~/ros2_study_myself/w1_study_workspace/src/w1_topic_demo/src/topic_publisher_demo.cpp:11`
> `pub_ = this->create_publisher<StringDate>("/w1/chatter", 10);`

---

## 1. 一句话结论

`create_publisher` / `create_subscription` 返回的 `SharedPtr` **就是那个发布者/订阅者的所有权凭证**：

> **没有活着的持有者 → 引用计数归零 → 对象析构 → 它从 ROS 图上消失。**

而 **"节点活着" ≠ "发布者活着"** —— 这是**两件独立的事**（实测见 §2）。

---

## 2. 现象（实测，原样保留）

三节点对照实验（`/tmp/w1_handle_ws`，代码见 §4）实跑输出：

```
[INFO] [keep_node]: keep_node：句柄存成成员 pub_
[INFO] [drop_node]: drop_node：局部句柄 use_count=1，马上离开作用域
[INFO] [capture_node]: capture_node：句柄被 lambda 捕获，use_count=2
```

```
$ ros2 node list
/capture_node
/drop_node
/keep_node
$ ros2 topic list | grep chatter
/captured/chatter        ← 不存成员、但被 lambda 捕获的：话题【在】
/keep/chatter            ← 存成成员的：话题【在】
                         ← /drop/chatter 不在！只放局部变量的：发布者已析构
```

> ⚠️ 注意 `/drop_node` 这个**节点还在**（`node list` 里能看到），
> **但它的发布者已经不存在了** —— "节点死活"和"发布者死活"是两件事。

---

## 3. 为什么会这样（原理）

### 3.1 rclcpp 的工厂函数**就是**返回 `shared_ptr`

```cpp
// /opt/ros/humble/include/rclcpp/rclcpp/publisher_factory.hpp:76
auto publisher = std::make_shared<PublisherT>(node_base, topic_name, qos, options);

// /opt/ros/humble/include/rclcpp/rclcpp/publisher_base.hpp:60
class PublisherBase : public std::enable_shared_from_this<PublisherBase>
```

- 工厂**内部已经把对象建好、并注册进 ROS 图**（创建了底层 `rcl_publisher_t` 句柄），
  然后把 `shared_ptr` 交给你 —— **你要做的只是"接住"它**。
- 继承 `enable_shared_from_this` 本身就说明：**设计者假定的持有方式就是 `shared_ptr`**
  （对比 `05_shared_from_this与bad_weak_ptr.md`）。

### 3.2 引用计数：最后一个走的人关灯

| 时刻 | `use_count` | 结果 |
|---|:---:|---|
| 构造函数里 `auto pub = create_publisher(...)` | 1 | 发布者存在，话题出现在图上 |
| 构造函数结束（局部变量销毁） | **0** | **Publisher 析构 → 话题消失** |
| 存成成员 / 被 lambda 捕获 / 放进容器 | ≥1 | 只要有人持有，就一直活着 |
| 最后一个持有者也销毁 | 0 | 这时才析构 |

### 3.3 那"直接 `new` 成堆指针"行不行？

| 方案 | 会不会漏 | 能不能用 | 为什么 |
|---|---|---|---|
| `new Publisher<T>(...)` 裸指针 | 要自己 `delete`，异常路径会漏 | ❌ | 你 new 出来的**不是**注册进 ROS 图的那个对象；rcl 句柄 / QoS / 类型支持全要重来 |
| `std::shared_ptr<T> p(new T)` | 不会漏 | 语法可行 | **两次分配**（控制块 + 对象），异常安全弱于 `make_shared` |
| **`std::make_shared<T>()`** | 不会漏、**一次分配** | ✅ 官方就是这么做的 | 控制块与对象一起分配；要么全成功，要么全不分配 |

> 结论不是"不能 new"，而是：**对象由 rclcpp 建好并把 `shared_ptr` 交给你了，你要做的就是接住它。**

## 4. 最小复现（完整可编译，放 `/tmp` 里做，不污染学习工作区）

```cpp
// handle_demo.cpp —— 三种持有方式对照
#include <chrono>
#include <memory>
#include "rclcpp/rclcpp.hpp"
#include "std_msgs/msg/string.hpp"

using String = std_msgs::msg::String;
using namespace std::chrono_literals;

// ① 正确：句柄存成成员 → 发布者一直活着
class KeepNode : public rclcpp::Node
{
public:
    KeepNode() : Node("keep_node")
    {
        pub_ = this->create_publisher<String>("/keep/chatter", 10);
        timer_ = this->create_wall_timer(1s, [this]() -> void {
            String msg; msg.data = "keep"; pub_->publish(msg);
        });
        RCLCPP_INFO(get_logger(), "keep_node：句柄存成成员 pub_");
    }
private:
    rclcpp::Publisher<String>::SharedPtr pub_;
    rclcpp::TimerBase::SharedPtr         timer_;
};

// ② 不存：只留一个局部变量 → 构造函数一结束，引用计数归零
class DropNode : public rclcpp::Node
{
public:
    DropNode() : Node("drop_node")
    {
        auto pub = this->create_publisher<String>("/drop/chatter", 10);   // 局部变量！
        RCLCPP_INFO(get_logger(), "drop_node：局部句柄 use_count=%ld，马上离开作用域",
                    pub.use_count());
    }   // ← pub 在这里析构 → Publisher 析构 → 话题从 ROS 图上消失
};

// ③ 不存成员，但被 lambda 按值捕获 → 有人持有，照样活着
class CaptureNode : public rclcpp::Node
{
public:
    CaptureNode() : Node("capture_node")
    {
        auto pub = this->create_publisher<String>("/captured/chatter", 10);
        timer_ = this->create_wall_timer(1s, [pub]() -> void {
            String msg; msg.data = "captured"; pub->publish(msg);
        });
        RCLCPP_INFO(get_logger(), "capture_node：句柄被 lambda 捕获，use_count=%ld",
                    pub.use_count());
    }
private:
    rclcpp::TimerBase::SharedPtr timer_;
};

int main(int argc, char ** argv)
{
    rclcpp::init(argc, argv);
    auto keep = std::make_shared<KeepNode>();
    auto drop = std::make_shared<DropNode>();
    auto cap  = std::make_shared<CaptureNode>();
    rclcpp::executors::SingleThreadedExecutor exec;
    exec.add_node(keep); exec.add_node(drop); exec.add_node(cap);
    exec.spin();
    rclcpp::shutdown();
    return 0;
}
```

验证命令：

```bash
source /opt/ros/humble/setup.bash
cd /tmp/w1_handle_ws && colcon build --packages-select handle_demo
source install/setup.bash
ros2 run handle_demo handle_demo &          # 后台跑
sleep 5
ros2 node list                              # 三个节点都在
ros2 topic list | grep chatter              # 只有 keep / captured，没有 drop！
pkill -f handle_demo
```

## 5. 要不要 / 什么时候用（判断标准）

| 情况 | 结论 |
|---|---|
| 节点类的发布者 / 订阅者 / 定时器 | **必须存成成员**（`pub_` / `sub_` / `tim_`） |
| 只在一个回调里临时用一下 | 可以靠 `lambda` 按值捕获（实测 `/captured/chatter` 存在，`use_count=2`） |
| "反正节点活着，丢就丢" | ❌ 丢的那一刻发布者就没了（实测 `/drop/chatter` 不存在） |
| 想让发布者活到程序结束 | 交给**活着的**对象持有（成员 / 容器 / 静态） |
| 想自己 `new` 一个来"延长寿命" | ❌ 没意义：你 new 的不是图上那个对象 |

## 6. 正确 ✗ 错误 对照

### ✗ 错误（会"看不见话题"的写法）

```cpp
DropNode() : Node("drop_node")
{
    auto pub = this->create_publisher<String>("/drop/chatter", 10);   // ❌ 没人接住
}   // 构造函数结束 → Publisher 析构 → 话题消失（节点还在，图上却没有它）
```

### ✅ 正确

```cpp
KeepNode() : Node("keep_node")
{
    pub_ = this->create_publisher<String>("/keep/chatter", 10);       // ✅ 存成成员
    timer_ = this->create_wall_timer(1s, [this](){ /* pub_->publish(...) */ });
}
private:
    rclcpp::Publisher<String>::SharedPtr pub_;                        // ✅ 所有权在这儿
    rclcpp::TimerBase::SharedPtr         timer_;
```

> 补充：`timer_` / `sub_` 同理 —— **`create_*` 系列全部返回 `SharedPtr`，全都要接住。**

## 9. 一句话复述（自测用，能背下来才算过）

> 我不再"想当然地以为节点活着、发布者就活着"：
> `create_publisher` 返回的 `SharedPtr` 是**所有权凭证**，**没人接住它就会析构、话题当场从图上消失**；
> 所以要么存成成员，要么让某个活着的对象（如 lambda 捕获）持有它；
> 而**自己 `new` 一个是没有意义的** —— 那不是我注册进 ROS 图的那个对象。
