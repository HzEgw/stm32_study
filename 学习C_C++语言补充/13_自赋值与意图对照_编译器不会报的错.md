# 13 · 自赋值与「意图 ↔ 代码」自检 —— 编译器**不会**帮你抓这类错

> **记录时间**：2026-09-24（夜）
> **触发场景**：手写参数 demo（`w1_param_demo`）时，在参数回调里想把"新周期"同步进成员变量，
> 结果写成了 **`report_period_ms_ = report_period_ms_;`（自己赋自己）**
> **发现时刻**：09-24 22:36 已自行修正为 `para.as_int()`，并重新编译（`0 warning`）✅
> **分类判定**：拿掉 ROS2 成立、换到 PC 也成立 → **C/C++ 语言 / 编码习惯问题** ✅

---

## 1. 一句话结论

1. **`x_ = x_;` 这种自赋值，编译器不会替你抓** —— 实测 **GCC 11.4 + `-Wall -Wextra -Wpedantic` 零警告**，
   而且 GCC **根本没有** `-Wself-assign` 这个开关（那是 Clang 的）。
   → **"编译通过 + 0 warning" ≠ "逻辑正确"。**
2. 它是**同一个毛病第 2 次复发**（09-23：想用 CH1 却写 `TIM_Channel_1`；想读 CCR2 却配了 CH1）→
   病灶只有一个：**"我脑中的对象" ≠ "手上的标识符"**。
3. 处方（5 秒自检）：每写完一行"**把外部值搬进内部状态**"的代码，立刻问三句 →
   **① 右边来源是外部变量还是 `this`？② 左右同名吗？③ 类型/单位对吗？**

---

## 2. 现象（原样保留）

```cpp
// w1_param_demo/src/para_demo.cpp —— 参数回调里（修正前）
else if (para.get_name() == "report_period_ms")
{
  report_period_ms_ = report_period_ms_;      // ❌ 自赋值：右边并没有取到 para 的值
  timer_ = this->create_wall_timer(std::chrono::milliseconds(report_period_ms_), ...);   // 仍按旧周期建
}
```
**修正后**（22:36）：
```cpp
  report_period_ms_ = para.as_int();          // ✅ 来源明确 = 本次被设置的参数
```

**为什么当时"看不到现象"**：那次实验里 `result.successful = false`（**拒绝**了设置）→
参数值本来就不会变 → **自赋值被"拒绝"这件事掩盖了**。
→ 一旦把 `successful` 改回 `true`，它就会现形（"参数显示改了，打印周期没变"）。

---

## 3. 为什么会这样（原理）

| 事实 | 说明 |
|---|---|
| `x = x;` 在 C++ 里**语义合法** | 对基本类型是良定义的、无副作用 → **编译器没有义务报** |
| 编译器**会报**的 | `-Wformat`（`%d` 配 `long`，我们实测过）、`unused variable`、类型不兼容、语法 |
| 编译器**不会报**的 | **自赋值**、逻辑写反、**变量名写错但类型相同**（`CH1`/`CH2`、`para`/`this`） |
| 所以 | 这一类错误**只能靠"人对照意图"**，工具指望不上 |

---

## 4. 最小复现（本机实测，不依赖 ROS）

```cpp
// /tmp/selfassign.cpp
struct S { long x_{0}; void f(long v) { x_ = x_; (void)v; } };   // ← 自赋值
int main() { S s; s.f(3); }
```
**实测输出（原文）**：
```
$ g++ -std=c++17 -Wall -Wextra -Wpedantic -c /tmp/selfassign.cpp -o /dev/null
（无任何输出，退出码 0）                       ← 0 warning！

$ g++ -std=c++17 -Wall -Wextra -Wpedantic -Wself-assign -c /tmp/selfassign.cpp
g++: error: unrecognized command-line option '-Wself-assign'    ← GCC 没有这个开关
$ g++ --version | head -1
g++ (Ubuntu 11.4.0-1ubuntu1~22.04.3) 11.4.0
```
> ⚠️ 对比：同一档 `-Wall` **会**报"格式串 vs 实参类型"（见 `学习C_C++语言补充` 里 `static_cast` 那篇的实测）。
> 也就是说：**编译器只查"类型层"，不查"语义层"。**

## 5. 怎么防（判断标准 → 变成条件反射）

**① 三问自检（5 秒）** —— 每写完一行"外部值 → 内部状态"（回调 / 中断 / 状态机 / 协议解析）：

| # | 问 | 今天这个 bug 的答案 |
|:---:|---|---|
| 1 | 右边的**来源**是外部变量，还是 `this`？ | 应为 `para`（外部）→ 却写了 `report_period_ms_`（自己） |
| 2 | 左右**是否同名**？ | **同名** → 一眼可见的破绽 |
| 3 | **类型/单位**对吗？ | `as_int()`（ms，整数） vs `as_double()` |

**② 每工程一张「意图 ↔ 配置对照表」**（09-23 就开出的处方，正好拦住今天这条）：

| 意图（我说要做什么） | 目标 | 来源（代码里必须写出处） |
|---|---|---|
| 把新周期同步给成员 | `report_period_ms_` | `para.as_int()` |
| 把新速度同步给成员 | `max_speed_` | `para.as_double()` |

**③ 收尾必做**：改完代码 → **重新编译**（今天做对了：22:36 改完就重编）→ 跑一次"能改变结果的开关"。

## 6. 正确 ✗ 错误 对照（今天 + 09-23 的同一模式）

| ✗ 错误写法 | ✅ 正确写法 | 为什么 |
|---|---|---|
| `report_period_ms_ = report_period_ms_;` | `report_period_ms_ = para.as_int();` | 自赋值 = 无操作 |
| 想用 **CH1** 却写 `TIM_Channel_1`（09-23） | 用与意图一致的 `TIM_Channel_2/3/4` | 通道号写错但**类型相同** → 编译器不报 |
| 想读 **CCR2** 却配 **CH1**（09-23） | 引脚/通道/CCR 三者对齐 | 同上 |
| 注释写"默认允许修改"，代码却是 `false` | 注释里**注明状态**：`// 实验：false = 拒绝（见截图）；正式版写 true` | 注释与代码状态不一致 → 三天后的自己会看错 |
| 实验结论**只留截图**（README 写"地址在…截图证明"） | README 里写**文字结论**一行（`GUI 3.0 / get 读回 2.0 = 被拒`），截图只做佐证 | 文字才能被检索 |
| `READEME.MD`（**第 3 次**：`clinet` / `READEME`×2） | 建文件后 5 秒回看名字 / 用模板复制 | 拼写错误会一直在 |

**"0 warning 陷阱"排查清单**：

| # | 情况 | 该问什么 |
